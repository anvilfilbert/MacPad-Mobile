# Match MacPad text File fidelity

PhonePad accepts regular plain-text Files up to exactly 25 MiB (`25 * 1024 * 1024` bytes), independent of filename extension after a URL is supplied, and rejects rich-text, binary-like, special, and oversized Files before editing through type, signature, decoding, and control-scalar rules. It supports UTF-8, UTF-8 BOM, and byte-order-marked UTF-16 little- or big-endian; a UTF-32 marker is explicitly unsupported. Legacy single-byte input is decoded strictly as Windows-1252, falling back to ISO-8859-1 only when Windows-1252 cannot represent the bytes. Their overlapping bytes cannot reveal an original label, so ambiguous input is named Windows-1252 and no other unmarked legacy encoding is inferred. Save As may explicitly choose either legacy encoding, and unrepresentable text produces an error rather than lossy conversion. A clean File is never rewritten; after editing, Save retains its encoding and dominant Windows, Unix, or classic-Mac line-ending style. New Documents default to UTF-8 with Unix `LF`, deliberately following the Apple-platform convention instead of MacPad's Windows `CRLF` default.
