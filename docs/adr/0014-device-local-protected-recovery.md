# Device-local protected recovery

Document Recovery data is stored as one atomic metadata-and-content envelope per item inside PhonePad's app container. The store preserves the prior verified generation until a replacement passes complete-protection and backup-exclusion checks. PhonePad implements no recovery synchronization and requests and verifies backup exclusion after every replacement, while recognizing that Apple controls platform backup and migration behavior. For unsaved edits to an existing File, recovery retains a security-scoped bookmark rather than a raw URL; bookmark creation and coordinated access occur only while security scope is active and are balanced immediately. Before an external File write, the envelope records the pending destination and intended digest so an interrupted Save can be reconciled. Save or Discard atomically replaces active recovery with a content-free cleanup marker before a Tab becomes clean or closes. Stale or denied access preserves recovered text and offers Locate Original or Save As. Any checkpoint failure visibly blocks further text mutation until Retry, Save, Save As, or Discard; the last verified checkpoint is never deleted by a failed generation.
